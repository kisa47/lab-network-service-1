# Network

Сеть — это группа устройств, соединённых для обмена данными.

## Общие панятия

- **IP-адрес** — уникальный номер устройства в сети (как почтовый адрес дома).
- **MAC-адрес** — физический адрес сетевой карты, «зашитый» на заводе.
- **Маршрутизатор (роутер)** — устройство, которое пересылает данные между разными сетями.
- **Коммутатор (свитч)** — устройство, соединяющее узлы внутри одной локальной сети.
- **DNS** — система, которая превращает понятные имена сайтов в IP-адреса.
- **DHCP** — это сетевой протокол, который позволяет устройствам автоматически получать IP-адрес и другие параметры для работы в сети.

## Полезные команды

### Базовая проверка доступности и маршрутов

```bash 
ping 8.8.8.8 # Проверка базовой доступности узла (отправка ICMP запроса)
ping -I eth0 8.8.8.8 # Проверить доступность через конкретный сетевой интерфейс
traceroute example.com # Показать путь следования пакетов до хоста (IPv4)
mtr example.com # Комбинация ping и traceroute в реальном времени
ip route get 8.8.8.8 # Показать, через какой интерфейс и шлюз пойдет трафик до цели
```

## Проверка интерфейсов и IP-адресации

```bash
ip -br address show # Краткий статус всех интерфейсов и их IP
ip address show # Подробная информация обо всех сетевых интерфейсах
ip a # краткий вид команды ip address show
ip route show # Вывести таблицу маршрутизации
ip r # краткий вид команды ip route show
ethtool eth0 # Проверить состояние линка, скорость и ошибки на физическом уровне
```

## Диагностика DNS

```bash
dig example.com # получить информацию, в том числе IP-адрес
nslookup example.com # альтернативная команда
dig example.com AAAA # для ipv6
dig example.com MX # почтовый сервер домена.
dig @8.8.8.8 example.com # запрос у конкретного DNS сервера
nslookup example.com 8.8.8.8 # тожесамое, но с помщью nslookup
host example.com # Простая утилита для конвертации имен в IP.
resolvectl status # Показать текущие DNS-серверы и настройки (для systemd-resolved).
```

## Порты, сокеты и сервисы


```bash 
ss -tuln # Показать все слушающие TCP/UDP порты с номерами (современный netstat).
ss -tulnp # То же самое, но с привязкой к процессам (требуются права root).
ss -s # Вывести общую статистику по сокетам.
netstat -tuln # Классическая проверка портов (может отсутствовать в новых системах).
netstat -r # Вывести таблицу маршрутизации 
nc -zv 192.168.1.1 22 # Проверить доступность конкретного порта (22/SSH).
nc -l 1234 # Запустить сервер на порту 1234 для прослушивания (Listen).
telnet example.com 80 # Проверить TCP-соединение на порт 80 (HTTP).
lsof -i :80 # Показать, какой процесс использует порт 80.
```

## Скорость и пропускная способность

```bash
iperf3 -s # Запустить сервер для теста скорости (на принимающей стороне).
iperf3 -c <IP_сервера> # Запустить клиент для теста скорости (на отправляющей стороне).
nload eth0 # Мониторинг трафика на интерфейсе в реальном времени.
bmon # Графический мониторинг пропускной способности в терминале.
```

## Анализ трафика (захват пакетов)

```bash
tcpdump -i eth0 # Начать перехват трафика на интерфейсе eth0.
tcpdump -i eth0 port 53 # Сниффить только DNS-трафик.
tcpdump -i any -w capture.pcap # Записать весь трафик со всех интерфейсов в файл.
```

## Частные сети

Приватные (частные) диапазоны IP-адресов определены стандартом RFC 1918. Эти адреса не маршрутизируются в глобальном интернете и предназначены для использования внутри локальных сетей. Для доступа в интернет из таких сетей применяется технология NAT (Network Address Translation).

Основные диапазоны IPv4:
| Диапазон (начало — конец) | Префикс CIDR | Маска подсети | Классическая маска | Количество адресов | Примечание |
|---|---|---|---|---|---|
| 10.0.0.0 — 10.255.255.255 | 10.0.0.0/8 | 255.0.0.0 | Класс A | 16 777 216 | Для очень крупных сетей |
| 172.16.0.0 — 172.31.255.255 | 172.16.0.0/12 | 255.240.0.0 | Класс B | 1 048 576 | Охватывает блоки от 172.16.x.x до 172.31.x.x |
| 192.168.0.0 — 192.168.255.255 | 192.168.0.0/16 | 255.255.0.0 | Класс C | 65 536 | Самый частый выбор для домашних роутеров |
