# Docker compose

Docker Compose — это инструмент для автоматизации развёртывания и оркестрации многоконтейнерных приложений, основанный на декларативном описании сервисов, сетей и томов в едином конфигурационном файле формата YAML (docker-compose.yml).

Docker Compose реализует парадигму IaC (Infrastructure as Code), позволяя формализовать и воспроизводить инфраструктуру приложения как код. Это обеспечивает возможность развёртывать идентичные окружения на разных машинах и в разных средах.

Docker Compose применяется для:

* разработки и тестирования многокомпонентных приложений;
* развёртывания микросервисных архитектур;
* автоматизации CI/CD-процессов;
* быстрого прототипирования и демонстрации сложных систем.

## Пример структуры docker-compose файла

```yaml
version: '3.9' # версия спецификации Compose.

services: # Список сервисов (контейнеров)
  app: # Веб-приложение (backend); 1-ый микросервис
    image: myapp:1.2.0 # Образ контейнера
    build: # Если образ невозможно получить из регистри или отсустсвует в система произвести сборку
      context: ./app # контекст сборки
      dockerfile: Dockerfile # Путь до докерфайла
    environment: # Переменные окружения контейнера
      - ENV=production
      - DB_HOST=db
      - DB_PORT=5432
      - REDIS_HOST=redis
      - RABBITMQ_HOST=rabbitmq
    volumes: # подключение постоянного хранилища данных
      - ./app:/app # проброс директории в контейнеер
    depends_on: # сервисы, от которых зависит данный сервис (в рамках 1 compose файла) 
      - db
      - redis
    networks: # к какой сети подключен контейнер
      - backend-net
    deploy: # параметры создания контейнеров
      replicas: 3 # количество экземпляров (реплик)
      restart_policy: # политика перезапуска
        condition: on-failure # перезапуск при завершении с кодом выхода отличным от 0 

  db: # PostgreSQL (база данных); 2-ой сервис
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: mydb
    volumes: # подключение постоянного хранилища данных
      - db_data:/var/lib/postgresql/data # подключение хранилища данных описанного ниже 
    healthcheck: # Проверка работоспособности контейнера
      test: ["CMD-SHELL", "pg_isready -U user"] # способ проверки командой
      interval: 10s # интервал проверки
      timeout: 5s # задержка после старта 
      retries: 5 # количество попыток подряд для признания контейнера нерабочим/рабочим
    networks:
      - backend-net

  redis: # Redis (сервис кэширования); 3-ий микросервис
    image: redis:7-alpine
    command: redis-server --appendonly yes # переопределние CMD из Dockerfile (использование другой команды при старте внутри контейнера)
    volumes:
      - redis_data:/data
    networks:
      - backend-net

  nginx: # Nginx (прокси и балансировщик нагрузки); 4-ый микросервис
    image: nginx:stable-alpine
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d # проброс директории с файлами настройек для web-сервера
    ports:
      - "80:80" # проброс порта хоста 80 на порт контейнера 80
    depends_on:
      - app
    networks:
      - frontend-net
      - backend-net

networks: # Виртуальные сети
  backend-net: # Сеть "бекенда" 
    driver: bridge # Тип сети (без доступа снаружи)
  frontend-net: № 
    driver: bridge 

volumes: # перечисление томов (постоянных хранилищ)
  db_data: # Том для БД (хранит данные после удаления контейнера, но не является директорией с прямым доступом)
  redis_data: # Том для кеширующего сервиса
```

## Основные настройки Docker Compose

### 1. Версия и структура файла
- **`version`** — определяет версию спецификации Compose. Влияет на доступность синтаксиса и функций.
- **`services`** — основной блок, где описываются контейнеры (сервисы) приложения.
- **`networks`** — определение сетей для взаимодействия контейнеров.
- **`volumes`** — определение постоянных хранилищ данных.

### 2. Настройки сервисов (services)

#### Из чего берётся образ
- **`image`** — имя и тег готового образа из реестра (например, `nginx:latest`).
- **`build`** — сборка образа из Dockerfile:
    - `context` — путь к контексту сборки (обычно `.`).
    - `dockerfile` — имя Dockerfile (если не стандартный).
    - `args` — аргументы для `ARG` в Dockerfile.

#### Переменные окружения
- **`environment`** — список переменных окружения, передаваемых в контейнер.
    - Можно использовать переменные хоста (`$VARIABLE`) или `.env`-файл.

#### Проброс портов и томов
- **`ports`** — проброс портов из контейнера на хост:
    - `"8080:80"` (хост:контейнер).
    - `"8080"` (случайный порт на хосте).
- **`expose`** — объявляет, какие порты использует сервис (для внутренней сети, не пробрасывает наружу).
- **`volumes`** — монтирование данных:
    - `type: bind` — привязка локальной папки (`./app:/app`).
    - `type: volume` — использование именованного тома (`db_data:/var/lib/postgresql/data`).

#### Зависимости и порядок запуска
- **`depends_on`** — указывает, что сервис зависит от других. Не гарантирует готовность, только порядок запуска.
- **`healthcheck`** — проверка работоспособности контейнера перед тем, как считать его запущенным.

#### Сетевые настройки
- **`networks`** — список сетей, к которым подключается сервис.
- **`network_mode`**:
    - `bridge` (по умолчанию) — в сети с другими контейнерами.
    - `host` — использует сеть хоста.
    - `none` — без сети.
    - `service:<имя>` — использует сеть другого сервиса.

#### Масштабирование и перезапуск (для Docker Swarm)
- **`deploy`**:
    - `replicas: 3` — количество экземпляров сервиса.
    - `restart_policy` — политика перезапуска (`on-failure`, `any`, `none`).

### 3. Настройки сетей (networks)

#### Типы драйверов
- **`driver: bridge`** (по умолчанию) — создаёт изолированную сеть для контейнеров.
- **`driver: host`** — использует сеть хоста (не изолировано).
- **`driver: overlay`** — для распределённых приложений в Swarm/Kubernetes.

#### Специальные параметры
- **`internal: true`** — делает сеть полностью изолированной от внешнего мира. Контейнеры могут общаться только друг с другом внутри этой сети.
- **`external: true`** — подключает уже существующую сеть, созданную вне Compose.

### 4. Настройки томов (volumes)

#### Типы томов
- **Именованные тома** (`volumes: db_data:`) — управляются Docker, данные сохраняются между запусками.
- **Bind-mounts** (`volumes: ./app:/app`) — монтирование локальной папки. Удобно для разработки.

#### Параметры томов
- Можно указывать драйвер (`driver: local`) и параметры монтирования (`o: size=10g`), если требуется специфичное поведение.

### 5. Краткая шпаргалка

| Настройка | Тип | Описание |
| :--- | :--- | :--- |
| `image` | string | Готовый образ |
| `build` | object | Сборка из Dockerfile |
| `environment` | list | Переменные окружения |
| `ports` | list | Проброс портов наружу |
| `expose` | list | Внутренние порты |
| `volumes` | list | Монтирование данных |
| `depends_on` | list | Зависимости сервисов |
| `healthcheck` | object | Проверка готовности |
| `networks.driver: bridge` | string | Изолированная сеть |
| `networks.internal: true` | bool | Полная изоляция от хоста |
| `deploy.replicas` | int | Масштабирование (Swarm) |

## Основные команды Docker Compose

### Управление жизненным циклом проекта

*   **`docker compose up`**
    Создаёт и запускает все контейнеры, описанные в файле `docker-compose.yml`. По умолчанию команда работает в активном режиме (*foreground*) и выводит логи всех сервисов.

*   **`docker compose up -d`**
    Запускает контейнеры в фоновом режиме (*detached mode*). Управление возвращается в терминал сразу после старта.

*   **`docker compose down`**
    Останавливает и полностью удаляет контейнеры, сети и тома, созданные командой `up`. Это основной способ очистки ресурсов проекта.

*   **`docker compose start`**
    Запускает уже созданные, но остановленные контейнеры.

*   **`docker compose stop`**
    Останавливает запущенные контейнеры.

*   **`docker compose restart`**
    Перезапускает работающие контейнеры.

### Работа с образами и сборкой

*   **`docker compose build`**
    Собирает или пересобирает образы, указанные в разделе `services.build` файла конфигурации.

*   **`docker compose pull`**
    Скачивает образы, описанные в `docker-compose.yml`, из реестра, но не запускает их. Полезно для предварительного обновления.

### Просмотр состояния и логов

*   **`docker compose ps`**
    Показывает список контейнеров текущего проекта и их текущий статус (запущен, остановлен).

*   **`docker compose logs`**
    Выводит логи сервисов. Без параметров показывает логи всех запущенных сервисов.

*   **`docker compose logs -f <service>`**
    Следит за логами указанного сервиса в реальном времени (аналог команды `tail -f`).

*   **`docker compose top`**
    Отображает список процессов, запущенных внутри контейнеров проекта.

### Выполнение команд внутри контейнеров

*   **`docker compose exec <service> <command>`**
    Выполняет указанную команду внутри уже запущенного контейнера. Например, для открытия оболочки: `docker compose exec app sh`.

*   **`docker compose run --rm <service> <command>`**
    Создаёт новый временный контейнер для выполнения команды и удаляет его после завершения. В отличие от `exec`, не требует, чтобы основной сервис был запущен.

### Управление конфигурацией и окружением

*   **`docker compose config`**
    Проверяет синтаксис файла `docker-compose.yml`, подставляет переменные окружения и выводит итоговую, объединённую конфигурацию. Помогает найти ошибки в файле.

### Дополнительные полезные команды

*   **Масштабирование (для Docker Swarm):**
    `docker compose up --scale <service>=3`

*   **Принудительное пересоздание:**
    `docker compose up --force-recreate`

*   **Очистка «мусора» (неиспользуемых объектов):**
    `docker system prune -a -f`
    Глобальная очистка Docker (удаляет неиспользуемые образы, сети и тома).
